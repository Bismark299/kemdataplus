The Key Discovery: You're Missing Required Headers
Look at the authentication requirements in the documentation:

javascript
// ✅ REQUIRED HEADERS FROM DOCS:
headers: {
  'Accept': 'application/json',           // ✅ You have this
  'Authorization': `Bearer ${token}`,     // ✅ You have this
  'Content-Type': 'application/json',    // ✅ You have this (for POST)
  'User-Agent': 'KemDataplus/1.0'       // ❌ YOU'RE MISSING THIS!
}
Your app is likely not sending the User-Agent: KemDataplus/1.0 header, which is required by their API. This is a big red flag for Cloudflare's bot protection!

🔍 Why This Causes the Cloudflare 403
Cloudflare sees requests without the proper User-Agent as suspicious bot traffic

After a few requests, Cloudflare blocks the IP with a "Just a moment..." challenge

Redeploy works temporarily because the new IP gets a fresh start, but the same pattern repeats

The documentation explicitly states:

"I do not recommend intentionally flooding the live MCBIS account. It can trigger a Cloudflare 403"

This confirms your issue is rate/pattern-based blocking, not a permanent blacklist.

🛠️ The Fix: Add the Missing Headers to ALL Requests
Update ALL your MCBIS API calls to include the proper headers:

javascript
// ✅ CORRECTED FUNCTION FOR ALL MCBIS REQUESTS
async function makeMcbisRequest(endpoint, options = {}) {
    const baseUrl = 'https://datahub.mcbissolution.com/api/v1';
    const url = `${baseUrl}${endpoint}`;
    
    const response = await fetch(url, {
        method: options.method || 'GET',
        headers: {
            'Accept': 'application/json',
            'Authorization': `Bearer ${process.env.MCBIS_API_TOKEN}`,
            'Content-Type': 'application/json',  // Required for POST
            'User-Agent': 'KemDataplus/1.0'      // ⭐ THIS WAS MISSING!
        },
        body: options.body ? JSON.stringify(options.body) : undefined
    });
    
    // Handle rate limiting properly
    if (response.status === 429) {
        const retryAfter = response.headers.get('retry-after');
        throw new Error(
            `MCBIS rate limit reached. Retry-After: ${retryAfter || 'not provided'}`
        );
    }
    
    if (!response.ok) {
        throw new Error(`MCBIS request failed with HTTP ${response.status}`);
    }
    
    return response.json();
}

📊 The "Retry-After" Header Handling
The documentation shows you should handle the retry-after header when you get a 429:

javascript
// ✅ PROPER RATE LIMIT HANDLING
async function getMcbisBalance() {
    const response = await fetch('https://datahub.mcbissolution.com/api/v1/walletBalance', {
        headers: {
            'Accept': 'application/json',
            'Authorization': `Bearer ${process.env.MCBIS_API_TOKEN}`,
            'User-Agent': 'KemDataplus/1.0'  // ⭐ STILL NEED THIS
        }
    });
    
    if (response.status === 429) {
        const retryAfter = response.headers.get('retry-after');
        throw new Error(
            `MCBIS rate limit reached. Retry-After: ${retryAfter || 'not provided'}`
        );
    }
    
    if (!response.ok) {
        throw new Error(`MCBIS request failed with HTTP ${response.status}`);
    }
    
    return response.json();
}
